# 知兽 MVP

知兽是一个本地运行的兽医 AI 病历工具。它把一次问诊按以下流程处理：

1. 浏览器录音或上传音频；
2. 生成可人工修改的逐字稿；
3. 结合已核对的既往背景，生成结构化 SOAP 病历；
4. 用确定性规则核对药名、剂量、频次、疗程、否定关系和信息来源；
5. 兽医人工确认后，才允许复制或导出病历；
6. 将会话关联到经人工核对的宠物档案，供后续复诊使用。

项目当前面向本机单人使用。临床数据、录音、数据库和 API 密钥默认只保存在本机，不进入版本库。

## 技术栈

- Python 3.12（当前验证环境：3.12.14）
- Flask 3.1.3
- Requests 2.34.2
- SQLite（Python 标准库）
- 原生 HTML、CSS、JavaScript，无 Node.js 构建步骤
- OpenAI 兼容的语音识别与 Chat Completions 接口；也支持豆包音频理解配置

`requirements.txt` 目前只声明 `Flask` 和 `requests`。上面的版本是本项目当前虚拟环境中已通过测试的版本。

## 本地运行

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py
```

然后打开 `http://127.0.0.1:5173/`。

把真实服务地址、模型名和 API Key 填入 `.env`。`.env` 已被 Git 忽略。缺少必要配置时，服务仍可启动，但对应模型功能会返回明确的 503 配置错误，不会生成占位结果冒充成功。

常用配置：

- `ZS_ASR_PROVIDER`：`whisper` 或 `doubao`
- `ZS_ASR_BASE_URL`、`ZS_ASR_API_KEY`、`ZS_ASR_MODEL`
- `ZS_LLM_BASE_URL`、`ZS_LLM_API_KEY`、`ZS_LLM_MODEL`
- `ZS_KB_MODE`：`placeholder`、`rag` 或 `off`
- `ZS_MAX_AUDIO_MB`、`ZS_HOST`、`ZS_PORT`

完整字段和注释见 `.env.example`。

## 主要功能

### 录音与转写

录音入口不要求预先建档。浏览器录音会转为单声道 16 kHz PCM WAV；豆包模式把音频按约 25 秒切片，并按顺序同步请求。所有片段成功后才一次性保存逐字稿，任一片段失败时不会保存不完整结果。

当前实现不是流式识别，也不是异步录音文件任务。产品层限制为最长 10 分钟、转写文件最大 20 MB；上传入口同时受 `ZS_MAX_AUDIO_MB` 配置约束。分段边界和模型识别结果仍需人工核对。

### SOAP 病历

新病历由模型直接输出结构化字段：

- S：主诉、既往病史、现病史
- O：客观
- A：评估
- P：计划

旧会话如果只有整段 S，会原样显示为“旧版原文”，不会用规则强行拆分。重新生成后才使用三个 S 子字段。

`app/grounding.py` 会把整份 SOAP 与“逐字稿 + 已核对的有效既往摘要”进行确定性核对。它不调用模型。修改逐字稿、既往摘要或病历会撤销原确认，并重新执行核对。

### 确认与导出

病历只有在兽医人工确认后才能复制或导出。确认闸门位于服务端，直接调用导出接口也无法绕过。确认后的病历再次修改时，确认状态自动失效。

### 宠物档案与会话关联

转写完成后，系统可以从逐字稿中提取疑似宠物资料，并保留每个字段对应的连续原文。候选资料只作为待核对草稿展示，不能静默写入档案。

兽医可以把本次会话关联到已有档案，或核对后新建档案。若候选值与已有档案冲突，界面要求逐项裁决。档案编号按创建顺序生成，例如 `Z00001`、`Z00002`，编号不会回收。模型提取的年龄、体重、免疫和驱虫信息按就诊记录保存；长期用药、过敏史和既往诊断属于档案背景。

档案页提供搜索、编辑和重复档案合并。代码已预留 `external_pms_id`，但尚未实现医院 PMS 同步。

### 会话历史和既往背景

每次录音、逐字稿、SOAP、核对状态和档案关联都保存在本机 SQLite。左侧会话列表可重新打开历史问诊；关联档案后显示宠物名和问诊摘要。

既往病历原文可生成结构化摘要，兽医修改并保存后，摘要才会作为独立 context 参与后续 SOAP 生成和核对。原始既往病历不会直接进入生成提示词。

### 知识库模式

知识问答默认是 `placeholder`，只收集需求且不调用模型。`rag` 模式只依据已经人工授权并导入的本地文档回答；任一结论缺少有效引用时，整次回答会被拒绝。当前语音病历主流程不依赖知识库功能。

## 数据与隐私

以下内容不会进入 Git：

- `.env` 和其他本地环境变量文件
- `.venv`、缓存和构建产物
- `data/` 中的 SQLite、录音和本地会话
- `.backups/` 中的数据库与代码快照
- 常见音频文件和 SQLite 文件

`event_log` 只接受代码中定义的安全字段白名单。音频、逐字稿、病历正文和问题原文不得写入事件日志。知识文档导入只读取本地文件，并要求填写授权来源。

## 核心数据关系

- `sessions`：一次问诊会话，包含录音元数据、逐字稿、SOAP、核对结果和确认状态。
- `pets`：宠物主档和稳定背景资料，使用内部 ID 与 `Z00001` 格式的展示编号。
- `visit_observations`：与具体会话关联的年龄、体重、免疫、驱虫等时序信息。
- `patient_audit`：人工建档、修改、关联和合并的审计记录。
- `patient_numbers`：档案展示编号序列。
- `kb_docs`、`kb_chunks`：本地知识文档与检索片段。
- `event_log`、`feature_requests`：去标识化事件和需求收集记录。

## 已知限制

- 当前没有用户账户、医院多租户或正式权限系统，只适合本机开发和验证。
- 语音转写没有说话人分离、流式字幕和异步长音频任务。
- 转写中的姓名、绝育状态等仍可能识别错误，因此档案写入必须经兽医确认。
- 核对引擎以词面规则为主，不能替代兽医对完整录音、逐字稿和病历的审阅。
- 未接入医院 PMS，`external_pms_id` 仅为后续集成预留。
- Flask 内置服务只用于开发；生产部署需要正式 WSGI 服务、身份认证、权限隔离和 HTTPS。

## 给后续开发者的约束

开始改动前先读项目上一级目录的 `AGENTS.md`。尤其不要破坏以下原则：

- 缺少真实配置时必须报错，不能伪造模型结果。
- `grounding.py` 保持确定性，不在其中调用模型。
- 临床内容不能进入事件日志。
- 病历修改必须撤销确认并重新核对。
- 未确认病历不能复制或导出，且服务端必须执行此限制。
- 档案候选必须展示原文并由兽医核对，不能由 AI 静默写库。
